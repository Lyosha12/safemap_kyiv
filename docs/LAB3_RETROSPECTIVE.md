# Ретроспектива: використання зовнішніх бібліотек у SafeMap (Лабораторна робота №3)

> **Чернетка.** Факти, проблеми й рішення нижче взяті з реальної роботи над проєктом.
> Перед здачею перепишіть оцінки та враження своїми словами (позначені _курсивом_ місця особливо).

## Які задачі планували вирішити

Після етапу 2 викладач зробив два зауваження:

1. HTML-сторінка генерувалась у C++ через output stream — треба винести її в окремі файли.
2. Локації були захардкоджені в коді — треба завантажувати їх із зовнішніх файлів (наприклад, CSV).

Звідси задачі для бібліотек:

| Задача | Бібліотека |
|---|---|
| Роздавати статичні файли сторінки й обробляти REST-запити | cpp-httplib |
| Читати й писати JSON (API, `config.json`) | nlohmann/json |
| Читати CSV з локаціями: заголовки, лапки, коми в назвах, UTF-8 | rapidcsv |
| Показувати мапу й будувати маршрут вулицями з часом у дорозі | Leaflet, Leaflet Routing Machine + OSRM |
| Отримувати реальний статус повітряної тривоги | cpp-httplib (`SSLClient`) + OpenSSL, сервіс ubilling.net.ua |
| Визначати, чи відчинений заклад зараз за графіком OSM | opening_hours.js (+ SunCalc) |
| Отримати реальні заклади селища | Overpass API (OpenStreetMap) |

## Чому саме ці бібліотеки

- **rapidcsv** — один заголовний файл, без залежностей і без збірки, підключається через `#include`.
  Розглядались альтернативи:
  - [vincentlaucsb/csv-parser](https://github.com/vincentlaucsb/csv-parser) — потужніший і швидший, але більший; для кількох сотень рядків його швидкість не потрібна;
  - [fast-cpp-csv-parser](https://github.com/ben-strasser/fast-cpp-csv-parser) — вимагає знати кількість колонок на етапі компіляції, а в нас колонки залежать від типу закладу;
  - власний парсер через `std::getline` — не обробляє лапки з комами всередині (`"вул. Доківська, 14"`), а такі адреси є в даних.
- **cpp-httplib** і **nlohmann/json** — уже використовувались у веб-версії етапу 2. Обидві header-only і з дуже простим API. Альтернативи (Boost.Beast, Crow, RapidJSON) або важчі в підключенні, або мають більш багатослівний API.
- **Leaflet + Leaflet Routing Machine** — безкоштовні, без API-ключів. Google Maps JavaScript API вимагає ключ і платіжну картку.
- **OpenStreetMap / Overpass** замість Google Places: Places API платний, а його умови забороняють зберігати дані у власну базу. Дані OSM відкриті (ODbL) — їх можна зберегти в CSV з атрибуцією.

## Наскільки просто було отримати, встановити й налаштувати

Header-only бібліотеки встановлюються копіюванням одного файлу в `include/`, без змін у `CMakeLists.txt` (крім `include_directories`). rapidcsv: завантажити `src/rapidcsv.h` з тегу `v8.84`.

Нюанси:

- **cpp-httplib на Windows/MinGW** вимагає `_WIN32_WINNT >= 0x0A00` і лінкування з `ws2_32` та `crypt32` (це вже було в `CMakeLists.txt` з етапу 2).
- JS-бібліотеки підключаються тегом `<script>` з CDN (unpkg), без npm.

## Документація

- **rapidcsv** — README з багатьма короткими прикладами покриває все потрібне. Параметри (`LabelParams`, `SeparatorParams`, `LineReaderParams`) простіше зрозуміти з коментарів у самому заголовку — сигнатури конструкторів із значеннями за замовчуванням.
- **cpp-httplib** — README з прикладами, детальної довідки API немає. Деякі речі довелося шукати прямо в `httplib.h`: наприклад, що `default_socket_options` вмикає `SO_REUSEADDR`.
- **nlohmann/json** — найкраща документація з усіх: окремий сайт з описом кожного методу і прикладами.
- **Leaflet** — хороша офіційна довідка й туторіали.
- **Leaflet Routing Machine** — документація стисла. Що профіль `foot` на демо-сервері OSRM насправді не працює, ніде явно не сказано (див. «Проблеми»).

## Чи було зрозуміло, які класи/методи використовувати

- rapidcsv: так. `Document` → `GetColumnIdx` → `GetCell<T>`. Для необов'язкових колонок зручно, що `GetColumnIdx` повертає `-1`, а не кидає виняток.
- cpp-httplib: так для маршрутів (`Get`, `Post`) і статичних файлів (`set_mount_point`). Менш очевидно — як налаштувати сокет (`set_socket_options`).
- nlohmann/json: так. Корисне відкриття — `json::parse(body, nullptr, false)` + `is_discarded()` замість `try/catch` для перевірки вхідних даних.

## Чи довелося писати багато надлишкового коду

Небагато. Довелося дописати:

- **власне перетворення чисел у rapidcsv.** `GetCell<double>` на некоректному значенні кидає виняток із повідомленням `stod`, яке нічого не каже користувачу. Тому клас `RowReader` читає рядок і сам перетворює його зі зрозумілою помилкою («некоректне число 'abc' в колонці 'lat'»);
- **розбір логічних значень** (`1/true/yes/так`) — rapidcsv не має вбудованого конвертера для `bool` з такими варіантами;
- **пошук файлів** `config.json`, `web/`, `data/` у поточній теці та на рівень вище — щоб запуск з CLion (`cmake-build-debug/`) працював без копіювання.

## Чи зрозумілою була поведінка бібліотек

Здебільшого так, але були сюрпризи (див. «Проблеми»): поведінка `SO_REUSEADDR` у httplib на Windows і профіль `foot` у публічного OSRM.

## Взаємодія бібліотек між собою та з власним кодом

Бібліотеки ізольовано по шарах:

- rapidcsv використовується лише в `CsvDataSource` (реалізація інтерфейсу `IDataSource`). Решта коду працює зі структурою `EstablishmentRecord` і не знає про CSV. Заміна джерела даних (JSON, БД) — це новий клас-нащадок `IDataSource`.
- nlohmann/json і httplib — лише в `main.cpp` (шар API). Класи предметної області (`RoutePlanner`, `Establishment`) від них не залежать.
- `EstablishmentFactory` (реєстр функцій-створювачів за ключем типу) пов'язує дані з CSV з ієрархією класів.

## Проблеми та як їх вирішили

| Проблема | Причина | Рішення |
|---|---|---|
| «Пішохідний» маршрут 4,6 км за 7,5 хв замість 1,2 км за 15 хв | демо-сервер `router.project-osrm.org` має лише автомобільний профіль і мовчки ігнорує `foot` | окремі сервери FOSSGIS: `routing.openstreetmap.de/routed-foot` і `/routed-car` |
| Замість темної мапи напис «API KEY REQUIRED» | CARTO Basemaps почали вимагати ключ | стандартні тайли OSM + CSS-фільтр `invert(1) hue-rotate(180deg)` |
| Після перезапуску сервер віддавав старі дані | на Windows httplib ставить `SO_REUSEADDR`, і два процеси можуть одночасно слухати один порт | `set_socket_options` з `SO_EXCLUSIVEADDRUSE` — другий екземпляр тепер одразу падає з поясненням |
| Відстань до всіх укриттів була 0 | `Coordinates::calculate_distance_to` був заглушкою з етапу 1 | реалізовано формулу haversine |
| Українські літери рендерились іншим шрифтом | у Plus Jakarta Sans немає базової кирилиці (лише `cyrillic-ext`) | Unbounded (заголовки) і Manrope (текст) |
| Overpass повертав 502 / таймаут | перевантаження публічних серверів | у скрипті — повтори і запасне дзеркало |
| Укриттів немає в OSM і на сайті громади | дані не внесені | перелік з карти «Укриття Коцюбинської СТГ» (KML-експорт Google My Maps) |
| Браузер не міг прочитати сервіс тривог | ubilling.net.ua не віддає CORS-заголовків | запит робить C++-сервер через `httplib::SSLClient` (потрібна збірка з OpenSSL) |
| CMake не знаходив OpenSSL з MSYS2 | `find_package(OpenSSL)` не шукає поряд із компілятором MinGW | `OPENSSL_ROOT_DIR` вираховується з шляху до компілятора |
| Сервіс тривог відповідав 429 | забагато запитів (кілька серверів + ручні тести) | інтервал 60 с (як `Cache-Control: max-age=60` у відповіді); при помилці зберігається останній успішний статус |
| Графіки роботи в OSM записані у складному форматі | `opening_hours` має власну граматику (дні, перерви, свята) | бібліотека opening_hours.js замість власного парсера |

## Що хорошого

- Header-only: нуль проблем зі збіркою та лінкуванням.
- rapidcsv коректно обробляє лапки, коми в полях, UTF-8 і BOM без додаткових налаштувань.
- nlohmann/json робить роботу з JSON у C++ майже такою ж зручною, як у Python.
- httplib дав повноцінний HTTP-сервер приблизно за десяток рядків.

## Що поганого

- httplib (~24 000 рядків) і nlohmann/json (~43 000 рядків) — великі заголовки, що суттєво збільшують час компіляції `main.cpp`.
- Деякі важливі поведінки httplib (налаштування сокета за замовчуванням) не описані в README.
- Безкоштовні онлайн-сервіси (OSRM-демо, CARTO, Overpass) можуть змінити умови чи бути недоступними. Тому потрібен запасний варіант: сервер сам оцінює час у дорозі.

## Що зробили б так само, а що інакше

- **Так само:** header-only бібліотеки; ізоляція rapidcsv за інтерфейсом `IDataSource`; окремі CSV для згенерованих (OSM) і ручних (укриття) даних.
- **Інакше:**
  - одразу перевіряти, що публічний сервіс справді повертає те, що очікуєш (профіль OSRM);
  - не покладатися на тайли без ключа від сторонніх провайдерів;
  - винести httplib в окремий `.cpp`, щоб не перекомпілювати його щоразу.
- **Можна додати:** Leaflet.markercluster для групування маркерів у центрі селища.
